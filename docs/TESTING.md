## 실제 Windows 화면에서 확인한 것

- 캘린더, 오늘 화면 진입, 일정 편집 대화상자 표시
- 한국어 일정 제목 등록, 달력 점·목록 반영
- 완료 체크와 취소선, 재실행 뒤 일정·완료 상태 유지
- 메뉴 추천 애니메이션과 결과, 결정한 메뉴의 이력 표시
- 숫자 게임 화면과 범위 밖 `9999` 입력: 안내 표시, 남은 기회 7/7 유지
- 라이트·다크 테마 및 다크 메뉴 화면의 표시
- 알림 미리 보기 버튼 호출 시 오류 로그 없음
- X로 닫아도 프로세스가 유지되며, 두 번째 실행은 종료되고 기존 메인 창이 다시 열림
- 배포 폴더의 **네이티브 MySchedule.exe 직접 실행**, 포함된 런타임으로 DB 생성·설정 저장 성공
- 테스트 SQLite `PRAGMA integrity_check` 결과 `ok`

테스트 데이터는 프로젝트 `tmp/ui-test`, `tmp/packaged-test`에 격리했습니다. 사용자 기본 데이터 폴더에는 샘플 일정을 넣지 않았습니다.

## 패키지 검증

- app-image, ZIP, EXE, MSI 생성 성공
- Maven 결과와 배포 폴더 `myschedule.jar`의 SHA-256 일치
- 배포 압축·설치 파일 체크섬 확인
- MSI 메타데이터: x64, 버전 1.0.0, 현재 사용자 설치, 시작 메뉴·바탕화면 바로 가기, 고정 UpgradeCode
- JavaFX / SQLite JDBC / SLF4J 모듈 로딩, SQLite 한글 저장·조회, FXML 로더 확인
- Java 런타임·외부 라이브러리 라이선스 포함
- 메인 창을 연 배포 프로세스 약 175 MiB, 런처 약 10 MiB 관찰. 작업 내용·화면 배율에 따라 메모리는 달라집니다. 시작 3초·CPU 1% 기준에 대한 정밀 성능 측정은 하지 않았습니다.

개발 중 발견한 전체 라이브러리 모듈 경로에서 SQLite/SLF4J가 정상 연결되지 않는 문제는 패키지 모듈 및 런타임 구성을 보완해 해결하고 네이티브 실행으로 재검증했습니다.

## 실제 사용 환경에서 추가 확인할 항목

아래 항목은 코드 구현은 포함되어 있으나 이번 자동화에서 전체 시나리오를 실증하지 못했습니다.

- 플로팅 아이콘 드래그·스냅, 일반 창 위 표시, 클릭/더블클릭 구분, 퀵 패널 위치
- 150~200% 화면 배율과 여러 모니터의 연결·분리 후 위치 보정
- 트레이 메뉴의 각 항목, Windows 시작 시 자동 실행
- 실제 시각 도달에 따른 토스트·Windows 트레이 알림의 표시와 절전 복귀 (알림 계산·중복·미루기는 자동 테스트 통과)
- EXE/MSI를 이용한 설치·제거 전체 과정 (파일 생성과 MSI 메타데이터는 확인)

전체 화면 게임 등의 독점 전체화면 위 표시와 Windows에서 끈 시스템 알림은 운영체제 설정에 영향을 받습니다.

## 범위

기획서의 필수 기능 및 반복·D-Day·검색·필터·즐겨찾기·게임 기록·아이콘 설정·중복 방지·자동 실행을 구현했습니다. 선택 항목에서는 다크 모드, 5/10분 알림 미루기, 메뉴에서 일정 추가, DB 백업을 포함했습니다. CSV 가져오기/내보내기, 반복 중 하루만 수정/삭제, 앱 내부 원클릭 복원, 향후 확장(클라우드 등)은 포함하지 않았습니다.
